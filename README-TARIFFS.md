# Как менять тарифы и оборудование на сайте

Раньше цены и модели роутеров были прописаны вручную в 6–7 файлах каждая.
Теперь всё хранится в двух файлах:

- `data/tariffs.json` — тарифы (цена, скорость, число ТВ-каналов, состав пакета)
- `data/equipment.json` — роутеры (название, характеристики, описание)

Всё остальное (карточки на страницах, кнопки, выпадающие списки в формах,
данные для Google в формате JSON-LD) собирается из этих двух файлов
автоматически скриптом `build.js`.

## Способ 1 — без установки чего-либо (проще всего)

1. Откройте `data/tariffs.json` (или `data/equipment.json`) прямо на GitHub,
   нажмите карандаш «Edit this file».
2. Поменяйте нужное значение, например `"price": 920` → `"price": 950`.
3. Нажмите «Commit changes».
4. Подождите 1–2 минуты — в репозитории появится **второй, автоматический
   коммит** от `site-builder-bot`, который обновит все .html файлы. Это
   делает GitHub Action, настроенный в `.github/workflows/build.yml`.
5. Готово — цена обновилась на всех страницах сайта, включая данные для
   поисковиков.

Если автоматический коммит не появился — откройте вкладку **Actions** в
репозитории и посмотрите, не упал ли workflow с ошибкой (обычно это опечатка
в JSON, например забытая запятая).

## Способ 2 — если работаете локально

1. Установите Node.js (один раз): https://nodejs.org
2. Отредактируйте `data/tariffs.json` / `data/equipment.json`.
3. В терминале, в папке сайта, выполните:
   ```
   node build.js
   ```
4. Закоммитьте и запушьте изменённые `.html` файлы обычным способом.

## Структура тарифа (data/tariffs.json)

```json
{
  "id": "hit100",
  "name": "ХИТ 100",
  "price": 920,
  "speedMax": 100,
  "tvChannels": 0,
  "featured": false,
  "badge": null,
  "features": ["До 100 Мбит/с", "Безлимитный интернет"]
}
```

- `featured: true` — тариф выделяется рамкой и бейджем (сейчас это СУПЕР ХИТ 200)
- `badge` — текст бейджа, например `"Популярный"` (нужен только если `featured: true`)
- `features` — список строк, которые показываются в карточке тарифа

Чтобы **добавить четвёртый тариф**, просто скопируйте один из блоков в массиве
`"tariffs"` и измените значения — новая карточка появится сама на всех
страницах, где есть блок тарифов.

## Структура роутера (data/equipment.json)

```json
{
  "id": "tenda-tx2-pro",
  "name": "Tenda TX2 Pro",
  "optionLabel": "Tenda TX2 Pro — WiFi 6, до 1.5 Гбит/с",
  "specsLine": "WiFi 6 • До 1.5 Гбит/с • 2-3 комнаты",
  "desc": "Современный роутер для квартиры...",
  "icon": "single",
  "featured": false
}
```

- `optionLabel` — как роутер выглядит в выпадающем списке формы
- `specsLine` / `desc` — текст в карточке роутера на главной странице
- `icon` — какую картинку показать в карточке. Доступные варианты:
  `single`, `single-strong`, `mesh2`, `mesh3` (одна антенна / усиленный /
  Mesh из 2 точек / Mesh из 3 точек). Если добавляете совсем новую модель —
  выберите ближайший по смыслу вариант, либо попросите добавить новую иконку
  в `build.js` (в объект `ROUTER_ICONS`).
- `featured: true` — на карточке появляется бейдж «Рекомендуем» (сейчас Tenda MW6)

## Что НЕ входит в эту систему (правится вручную, как раньше)

- Тексты FAQ, статьи (`faq.html`, `wifi-routery.html`, `skolko-internet-nuzhno.html` и т.д.)
- Заголовки `<title>` и `<meta description>` — в них цены упоминаются в
  живом, «человеческом» тексте (разном для каждой страницы), поэтому их
  правка автоматизирована не была: слишком высок риск сделать корявую
  формулировку. Их стоит проверять руками при изменении цен раз в
  сколько-то месяцев.
- Внешний вид карточек (`styles.css`) — дизайн, а не данные.

## Как устроена сборка технически

- `templates/*.html` — исходники страниц с метками
  `<!-- BUILD:ИМЯ_БЛОКА --> ... <!-- END:ИМЯ_БЛОКА -->` и токенами вида
  `{{PRICE_MIN}}`. Эти файлы менять почти никогда не придётся — только если
  меняете саму вёрстку карточек тарифов/роутеров.
- Файлы `.html` в корне репозитория — то, что реально видит браузер и
  поисковик. Это результат сборки, его можно не трогать руками вообще:
  он полностью перезаписывается из `templates/` при каждом запуске
  `build.js`.
